# tabnotes

Firefox MV2 extension: TypeScript under `src/`, bundled by esbuild into `dist/`, pages in plain DOM. See README.md for usage and docs/DEVELOPMENT.md for behaviour, build, release and tests.

## Rules

- Firefox loads `dist/`, the output of `scripts/build.js`; nothing in `src/` runs as it is. No React, no Tailwind, no component library, no dev server (the CSP blocks HMR and pages load from `moz-extension://`). Output is not minified: it stays reviewable and the network-API scan stays meaningful. The build keeps the relative paths of `src/`, so page URLs (`note/note.html?id=...`) do not change and open note tabs survive an update.
- `package.json` is `private` with exact versions, and `package-lock.json` is committed. It has no `version` (the tag is the version, and `manifest.json` at the root holds the placeholder `0.0.0`) and no `type` (`scripts/` and `tests/` are CommonJS; `require()` still loads a `.ts` with `export`). `web-ext` is not a dependency: it runs via pinned `npx` from `Taskfile.yml` for lint/build/sign.
- `engines.node` is `^22.18.0 || >=23.6.0`: tests `require()` `.ts` files without a flag, which fails on 22.17 and 23.5 (checked on real binaries).
- TypeScript is erasable only (`erasableSyntaxOnly`: no `enum`, no parameter properties), because node loads `.ts` directly. `skipLibCheck` stays: mermaid's `.d.ts` imports `type-fest`, a mermaid devDependency that is not installed; the cost is that `src/note/codemirror.d.ts` is not checked itself. `tsconfig.json` maps `codemirror/lib/codemirror.js` to `./node_modules/@types/codemirror/index.d.ts` because `@types/codemirror` does not declare that path; a bare `codemirror` value is TS5090 and `baseUrl` is gone on TypeScript 7.
- The code is MIT (`LICENSE`, `license` in `package.json` and the lockfile root). Bundling drops third-party license text, so the package ships it in `dist/THIRD_PARTY_LICENSES.txt`: `thirdPartyNotices` writes one section per non-dev lockfile entry, keyed by lockfile path as nested versions differ. `vendor/mermaid.min.js` is prebuilt and the lockfile does not describe what it bundles, so those texts are committed in `scripts/mermaid-bundled-licenses.txt`, re-checked on a mermaid update (docs/DEVELOPMENT.md, Updating dependencies); a test holds the mermaid version in its header equal to the installed one, so an update fails until then.
- `browser_specific_settings.gecko.data_collection_permissions` must stay in the manifest: AMO rejects uploads without it.
- No runtime network access and no remote URLs in extension sources (`tests/static.test.js` enforces this: the URL and HTML-sink scans walk `src/`, the network-API scan runs on `build()` output, which is what covers third-party code). Third-party code is exact-pinned npm dependencies, whose bytes the lockfile's integrity hashes check, and `tests/deps.test.js` checks that every version is exact and consistent across `package.json`, the lockfile and `node_modules`, and holds mermaid and CodeMirror on their majors (mermaid's latest major is 5.5 MB). marked, CodeMirror and highlight.js are bundled into `note.js`; the language set is `highlight.js/lib/common`, 36 languages. CodeMirror's CSS and its dialog addon's are `@import`ed in `note.css` before `src/styles/base.css` and the note rules, so overrides still win. highlight.js has no CSS import, as one `@import` cannot serve two modes: `note.css` holds token-based `.hljs-*` rules. Mermaid alone is not bundled: the build copies `node_modules/mermaid/dist/mermaid.min.js` to `dist/vendor/mermaid.min.js`, and `loadMermaid` adds a `<script>` tag for `../vendor/mermaid.min.js` on the first diagram, which keeps the page fast and leaves its failure handling as it is. `fetch` counts only as a bare or `window`/`globalThis`/`self` call: mermaid bundles KaTeX, whose parser has its own `.fetch()` method.
- The manifest `content_security_policy` is what keeps rendered note content (markdown images, mermaid image shapes, `<img>` in mermaid HTML labels, CSS `url()`) from loading remote URLs: `default-src 'self'` covers every fetch type it does not list, `img-src` adds only `data:` and `blob:`, `style-src` adds `'unsafe-inline'` because mermaid writes `<style>` elements and style attributes. The MV2 default `script-src 'self'; object-src 'self'` stays, never `'unsafe-eval'` or a remote source; `tests/static.test.js` checks the exact policy.
- No inline scripts or `on*` attributes in HTML: the MV2 CSP blocks them.
- Permissions stay `storage`, `tabs`, `sessions`.
- Render user data with `textContent`. The only `innerHTML` is `renderPreview` on the note page (enforced by a static test): `marked.lexer`, then `previewBlocks`, then one `<div data-line="n">` per top-level block around `marked.parser([token])`. `n` is a number. `previewExtension` closes what marked leaves unescaped: raw HTML (`escapeHTML` as the html renderer), image alt text (its default `image` writes it unescaped, so the override escapes every value and keeps `cleanUrl` behaviour, which it has to copy as marked does not export it), and text after an inline `<pre>`, `<code>`, `<kbd>` or `<script>` (the `inlineText` tokenizer clears `inRawBlock`, as the `text` renderer has to keep honouring `escaped`: `listitem` uses it for loose checkboxes). Link `href` and `title`, table `align`, `codespan` and heading or strong text are safe in the defaults; tests in `tests/notes.test.js` pin this, so re-run them on a marked update. A later `image` renderer returning `false` falls back to this override only if it is registered in a separate `marked.use`; in the same object it replaces the override. An image reference becomes `imageHTML` output: `imageIdFromHref`, the only id validation, keeps the id to a uuid and the alt text goes through `escapeHTML`. Code goes through `codeBlockHTML`, which always returns a string: a `div.code-block` around highlight.js output (it escapes the code; the language never reaches an attribute) or escaped text in `<pre><code>`, with a `button.copy`, so `pre` and `code` are not direct children of a block and the button does not scroll with the code (a rule on a preview block must reach through the wrapper: `.preview > *` is the `div[data-line]`); only mermaid returns a bare `pre.mermaid`, without wrapper or button. Tokens are lexed fresh for every render, never cached: marked's `listitem` mutates loose items, so parsing the same tokens twice doubles their checkboxes. Mermaid writes its sanitized SVG into the `pre.mermaid` nodes itself; that relies on `securityLevel: 'strict'` and the `secure` keys passed to `initialize` (mermaid's defaults, which stop `%%{init}%%` directives from lowering it, plus `themeCSS`, `fontFamily`, `altFontFamily`, whose values mermaid only brace-checks before putting them into CSS). Keep that list a superset of the bundle's default after a mermaid update; a note test checks it. None of this stops remote loads (image shapes `A@{ img: ... }` and `<img>` in labels pass both); the CSP does.
- Every `browser.*` call that can reject is handled and logged via `console.warn` with a `tabnotes: <what>:` prefix: a `.catch` on single calls, a `try/catch` around `getKeys` and the `Promise.all` in `recovery.ts` `refresh()`.
- If the note page cannot load its note it must not enable the editor: a save would overwrite the stored note with an empty one. Same for the options page and `settings` / `fontSize` / `theme`.
- The note editor is CodeMirror 5 over the hidden textarea, created synchronously right after a successful load (no `await` between showing the page and `fromTextArea`), so it exists before `stop`, the stop handler or `onChange` can run and a failed load creates none. `let cm: Editor | null` with `!` at the reads in closures checks nothing here (TS drops narrowing in closures), so this order stays protected by tests and review. `note.ts` imports `codemirror/lib/codemirror.js`, never bare `codemirror`: an esbuild alias matches by path prefix, so one on the bare name would also catch `codemirror/mode/...`. The `changes` handler ignores `origin === 'setValue'`: adopting another tab's content must not schedule a save.
- Preview interactions are delegated listeners on `previewEl`. An edit from the preview goes through CodeMirror, never to storage or the DOM: a checkbox click calls `cm.replaceRange(..., 'toggle')` on the character after `[` (an origin without `+` keeps it its own undo step, and not `setValue`, so the `changes` handler saves it), then flushes the render. `preventDefault` always runs, so a box's state comes only from rendering. Only toggling is blocked on a stopped tab; copy, jump and scroll sync write nothing. A jump there only moves the cursor: `stop` sets `readOnly: 'nocursor'`, under which `cm.focus()` does nothing and `setCursor` does not scroll, so the editor neither takes focus nor shows the line (docs/DEVELOPMENT.md, Manual verification). After a toggle, focus returns to the box only if `document.activeElement` is the body: the render removed the old box, so anything else means the user moved on while diagrams drew. With `renderer.pending()` a click or double-click only flushes, because a stale preview's checkbox index and `data-line` do not match the source.
- Tokens have no source offsets, and nested `raw` is stripped of indentation and `>`, so `taskOffsets` maps a checkbox to its `[` with a sentinel lex: it inserts `\uE000 + k + \uE001` after each task-like line's box, also on an empty item, and lexes the copy, so marked itself decides what is a task. Sentinels can change the structure of contrived notes, so it refuses rather than ticks the wrong line: `null` overall when the source already holds a sentinel character, when the task counts differ, or when the flip check fails; a `null` entry when a task has no sentinel or its text differs from the real task at that index. The flip check flips every mapped box in the real source, lexes that, and passes only if exactly the mapped indexes changed `checked`: offsets rise with the index, so this proves each mapping, where text alone does not, as next to identical tasks a shifted index still compares equal. It costs a third lex per click. A refusal logs `tabnotes: toggle task:` and leaves the note alone. The mapping is checked against marked 15.0.12 by chosen cases and by the seeded `preview mapping properties` test, whose note count and seed are constants: after a marked update, raise the count and try other seeds locally (docs/DEVELOPMENT.md, Updating dependencies), as a wrong mapping is rare.
- Task checkboxes are `input[type=checkbox]:not(.mermaid *)`, in both the click match and the index: a mermaid label can carry a sanitized `<input>`, which must not shift the index. The copy button's selector excludes diagrams the same way.
- Block anchors: `previewBlocks` gives each top-level block but `space` its source line by a sequential `indexOf(token.raw, cursor)`. Link definitions have no token, and a blockquote's `raw` can differ from the source, so a block not found takes the line of the next text after the cursor, and the cursor stays. Lines never go backwards, so `scrollAnchors` gets pairs already sorted and does not sort them. They only steer jump and scroll position, and a jump lands on a top-level block: anywhere in a list goes to the start of the list. Readers use `previewEl.children` only, as diagram labels may carry `data-*` of their own.
- Scroll sync runs only with both panes visible. The pane last interacted with (`wheel`, `pointerdown`, `keydown`, `focusin`) drives and scroll events on the other one are ignored, or a preview shrinking in a re-render would clamp its `scrollTop` and move the editor during typing. The echo guard stores the value written and skips one event within 1px of it; a boolean is wrong, as scroll events are asynchronous and a write that changes nothing fires none. Anchors are read live on each sync, and it re-runs after every diagram pass, on an image `load` (captured on `previewEl`, as it does not bubble) and on a mode change, before `cm.focus()` hands the drive to the editor. A driving pane with no scroll range writes nothing: its anchors would send the other pane to the top on every render. `position: relative` on `.preview` is what makes `offsetTop` usable; a static test pins it, as the fake layout cannot show it.
- The copy button uses `navigator.clipboard.writeText` in the click handler with no `clipboardWrite` permission. Whether Firefox allows that is unverified (docs/DEVELOPMENT.md, Manual verification); the fallback is dropping the button or asking the owner, not adding a permission.
- `fontSize` is its own storage key, not part of `settings`: Settings writes `settings` whole on every input, so note tabs writing into it would race it. Font shortcuts only write the key; every tab, the writer included, applies it from `storage.onChanged`.
- `theme` is its own storage key for the same reason: Settings writes it, every tab applies it from `storage.onChanged`, and a missing or unknown value means `system` (`themeFrom`). `storage.local` is async, so `src/theme.ts`, a blocking `<script>` in the `<head>` of all three pages, before the stylesheet (a static test pins it), sets `data-theme` on the root from a `localStorage.theme` mirror before first paint. The mirror serves that paint alone and nothing else reads it. Storage stays the source of truth: `theme.ts` corrects `data-theme` and the mirror from it, `data-theme` first so a throwing `localStorage` still changes the theme, and registers `onChanged` before the read, with a changed flag, so an older loaded value cannot undo a newer change. An empty or invalid mirror sets `system`, which CSS treats as no attribute.
- Colours: each `--color-*` token is `light-dark(<light>, <dark>)` on one line of `base.css`, with opaque hex values (a static test parses them), so no dark block repeats the list. `:root` has `color-scheme: light dark` and `[data-theme=light]` / `[data-theme=dark]` pin it, so System mode is CSS only: an OS switch needs no JS and cannot flash. `color-scheme` also colours scrollbars and native controls, which is why `.field select` takes only the shared size, font, border and padding. `note.css` overrides every coloured selector of CodeMirror's and the dialog addon's CSS with tokens, and has its own rule for each coloured selector of highlight.js's `github` theme. A static test compares them against those files, property by property, with a list of selectors that need none: features `note.ts` does not enable (active line, matching tags, rulers, gutter markers, fat cursor, diff mode), `::-moz-selection` (the later `::selection` rule wins) and `.hljs` selectors covered by a shorter one in the same rule, so enabling such a feature means adding its override and taking it off the list. `.hljs`, `.hljs-subst`, `.hljs-emphasis` and `.hljs-strong` set the text colour explicitly, or they would take the colour of an enclosing blockquote, string or section. The search hint's colour is inline in `search.js`, so it takes `!important`. Syntax colours are role tokens shared by CodeMirror and highlight.js, and comments use `--color-muted`. Each highlighter's classes map to roles as its upstream palette did, not by concept (`.cm-builtin` is title and `.hljs-built_in` builtin, `.cm-type` tag and `.hljs-type` keyword, `.cm-meta` muted and `.hljs-meta` constant), so the same code can differ in colour between editor and preview. Light colours therefore differ slightly from the old CodeMirror and `github` palettes, on purpose: keeping both exactly would take about 25 tokens.
- Mermaid theme: SVGs are static, so a change of the effective theme redraws them. `note.ts` does not read `data-theme`, which would depend on listener order against `theme.ts`: it reads `theme` in its load and `onChanged`, with the `fontSize` flag pattern. `mermaid.initialize` has one call site, in `drawDiagrams` straight after `await loadMermaid()`, ahead of the hidden and `live` returns, and runs on every pass that has a diagram to draw, so it needs no record of the configured theme and a hidden preview picks up the theme in `cycle`. The order matters: `mermaid.min.js` has a window `load` listener that runs every `.mermaid` node unless `startOnLoad` is false, and the `await` continuation is a microtask of the script's `load`, which comes first. It always passes the full config, as it rebuilds from defaults. `theme` stays out of `secure`, so a note's `%%{init}%%` can pick its own diagram theme. A failing `initialize` logs as `draw diagrams` and is retried on the next pass. The `onChanged` listener runs before the load, so its `theme` branch calls the `onTheme` hook, assigned once the editor exists, when the `matchMedia` `change` listener is registered too; a change during the load or on a failed-load page therefore cannot throw. Both call `applyDiagramTheme`, which does nothing if the effective theme did not change, clears the cache and returns if the preview holds no `pre.mermaid`, so an OS switch does not re-render every open tab. Otherwise it calls `renderPreview()` itself, not `renderer`: `flush` does nothing with no call pending and `schedule` leaves a window where a run in flight writes old-theme SVGs into the cleared cache. The synchronous render disconnects that run's nodes, which `drawDiagrams` skips, so no counter like `previewHides` is needed. Diagrams shrink to source text during the redraw, so it captures `scrollTop`, restores it after the pass and calls `syncScroll` again, as the chained sync ran on the clamped position. A hidden preview restores nothing, and two changes within one redraw may keep the clamped position of the second. The restore overwrites a scroll made during the redraw and is lost if the preview is hidden during it (docs/DEVELOPMENT.md, Known limitations): neither is worth extra state.
- Storage is one key per note (`note:<id>`), never a shared map: many note tabs are open at once and each save writes only its own key. The one shared map is `imageOrphans`, which only the background page writes, so that race does not apply.
- No code path may load all of storage: `get(null)` would read the bytes of every image. Read `getKeys()` (Firefox 143, why `strict_min_version` is 143), then `get` only the keys needed. Image values are read one id at a time by the note page, and never by the background page or All notes.
- Images are stored as `image:<uuid>` = `{dataUrl}`, global ids rather than per-note keys, so a reference copied into another note keeps working and one sweep handles every kind of cleanup: note removal, bin purge and blank notes need no image code. The value is a data URL string, not bytes: MDN lists `ArrayBuffer` as generally unsupported in `storage.local`, and a string works directly as `src` with no `blob:` URL lifecycle. Firefox 136+ allows 512 MB data URLs; before that the 32 MB limit was below the roughly 33 MB of base64 of a 25 MB image. The CSP already allows `data:` images.
- The note text holds `![name](tabnotes-image:<uuid>)`. The `marked` image renderer turns it into `<img data-image>` with no `src`, as the custom scheme would only be a CSP violation, and returns `false` for every other URL, so remote and `data:` images keep the `previewExtension` image renderer. After each render, unless the preview is hidden (then `cycle` draws once it is shown, also for a read that finishes while hidden), the preview pass sets `src` from a page-level map of id to read promise: one read serves every render while it is in flight, an id no longer on the page leaves the map, and a failed read leaves it so a later render retries.
- An image is inserted through `insertImages` in `note.ts` (CodeMirror's `drop` and `paste` events): its key is written before the reference enters the text, so a refused or failed image changes no text and keeps the selection. `checkImageFiles` applies `MAX_IMAGE_BYTES` (25 MB) before the read. A `markText` with `clearWhenEmpty: false` holds the position during the read; `find()` is undefined after adoption or an edit removed the range, and then the cursor is the fallback. `stopped` is checked before each read and write and before the insert: a stopped tab inserts nothing and the sweep collects what it wrote. On paste, non-empty `text/plain` wins over an image unless `pasteIsText` finds it a lone URL or absolute path, which Copy Image, file managers and the preview's own data URLs put next to the image; office cells stay text. The `document` `dragover` / `drop` guard stops a file dropped outside `cm.getScrollerElement()` from navigating the tab; CodeMirror's drag handlers sit on the scroller only, so scrollbars and the search dialog count as outside. It is registered once the editor exists, so the failed-load and invalid-id pages have none: they hold no editable note. In a drop holding an image, other files are skipped and named in the message, as `preventDefault` also stops CodeMirror from handling them. A failed note save or removal of a cleared note shows the `save-error` banner until a write lands, since images can fill the quota, unsaved text dies with the tab and a note that failed to clear returns on reload; it is its own element so it cannot overwrite an insert message or be cleared by one. Both messages take the grace days from `STORAGE_FULL_HINT`, so `note.html` holds no such text.
- `renderPreview` puts `<img>` nodes that have a `src` back into the new HTML, by id, before any layout: a new node has no height until it loads, and a clamped `scrollTop` is not restored when the preview drives or the editor is hidden. `imageHTML` sets `draggable="false"`: a drag carries the `src` as text, and CodeMirror would insert the data URL into the note.
- The background `purge` sweeps images after removing expired notes, also when nothing expired: `sweepImages` over all storage keys, the notes and `imageOrphans`, never image values. Referenced ids (binned notes count) leave `imageOrphans`, new unreferenced ids enter with the sweep's time, and ids unreferenced for the 7-day grace are removed. The grace runs from the first sweep that found an image unreferenced, not from its creation, so undo, clearing a note and moving a reference between notes are covered for an image of any age. A failed `remove` keeps its ids in the map for the next sweep, a failed read removes and writes nothing, and the map is written only if it changed (`orphansAfterFailedRemove`, `sameOrphans`). Purge and sweep share one read, and an expired note whose `remove` failed stays in the notes passed to `sweepImages`, so its references still count. When images are due to go, the keys and notes are read again right before the `remove` and `withoutReferenced` drops ids that gained a reference meanwhile, from both the removal and the map, so a later removal of that reference starts a new grace; a failure of that read writes nothing, so the first sweep's map changes go too. It filters the first sweep and never sweeps again: a second sweep could remove an id referenced on the first read on a stale map entry. There are no storage transactions, so a save landing after that read, or text still in a tab's save debounce, is not seen: this narrows the race, it does not close it (docs/DEVELOPMENT.md, Known limitations). A reference added and removed between two sweeps is not seen either, and does not restart the grace.
- Storage is the source of truth for bin state and the title. A note page sets `deletedAt` only via its own Restore button; otherwise it adopts `deletedAt` and key removal from `storage.onChanged` (registered before the load; values older than its in-memory `updatedAt` are its own late echoes and ignored). `onChange` applies the title next to `showBin()` in both the `saver.pending()` branch and the main path, ahead of the return on unchanged content, as a rename from another tab has the same content. An open rename input keeps its text.
- Title templates: `expandTitle` runs once, at creation and at rename commit, and `note.title` holds the plain result, so `Note` does not change and All notes, search and the bin need no template code; `settings.defaultTitle` alone stays a template. It is one `replace` pass over `\{[^{}]*\}` with a callback, so a value holding `{date}` or `$&` stays as it is within that pass, and `{{date}}` gives `{2026-11-01}`. The pass is per expansion: reopening shows the expanded text, and a commit of changed text expands all of it again. A placeholder it cannot evaluate stays literal, which covers an unknown variable or function and a wrong argument (`trunc` takes `^[1-9]\d*$`). Variables are looked up with `Object.hasOwn`, so `{constructor}` and `{__proto__}` stay literal. The result is trimmed, and an empty one is the caller's to handle: `DEFAULT_TITLE` at creation, the previous title at rename. `titleVars` uses local getters, never `toISOString`, pins `{weekday}` to `en-US` like `shortDate`, and gives `{host}` for `http(s)` only (`canOpen`): `about:` has no host, and a `moz-extension:` hostname is a uuid, which a toolbar click from a note tab would put in the title. `trunc` counts code points, so it cannot split a surrogate pair. `{tab}` and `{host}` come from `current.openerTabId` and `tabs.get`, awaited after the `stored === null` guard and before the page is shown: `onChanged` is registered before the load and `early` is read after this wait, so a change landing during it wins (a test holds the read), and `warnOr('get source tab', null)` means a closed opener never blocks the load. The read happens for existing notes too, as rename uses it, and `tabs` already gives `title` and `url`. `TITLE_HINT` is the one text of the hint, set from code on the note page and in Settings like `STORAGE_FULL_HINT`, and holds no URL, as `tests/static.test.js` scans `src/`.
- No template library: the CSP has no `'unsafe-eval'`, which rules out everything compiling with `new Function` (Handlebars, EJS, Nunjucks, Eta), and Mustache has no filters. LiquidJS 10.30.1 has no eval, but `defaultOptions.fs` references an `XMLHttpRequest` loader, which stays in the bundle and fails the network scan, and it adds about 185 KB unminified.
- Rename state is one `renaming` variable in `note.ts`, holding the text captured at open, `null` when closed. Commit, cancel and `stop` all go through `closeRename`, which clears it before hiding the input, and `commitRename` returns on `null`, so nothing depends on whether Firefox fires blur on a hidden element. Text equal to that baseline, both trimmed as the result is, does nothing, so opening and closing cannot re-expand a stored title holding braces, and cannot revert a rename adopted while the input was open. Blur commits unless `document.activeElement` is still the input: switching tab or window blurs it but leaves it active, and a half-typed title must stay open. The input's keydown ignores `e.repeat`, so an Enter held to open it does not close it, and `#title`'s calls `preventDefault` on Space, which would otherwise replace the selected title. `#title` is `role="button"` and named by its text, and the input's `aria-describedby` is the hint. The hint's `mousedown` is `preventDefault`ed, as it cannot take focus and a press would blur and commit. `insertImages` skips its final `cm.focus()` while the input is active, as a read of up to 25 MB can end mid-rename. The `document` Ctrl+E listener still calls `preventDefault` from the input but skips `cycle`, whose `cm.focus()` would commit mid-typing, and Firefox's own Ctrl+E does not run. A commit goes through `saver` only, with `schedule()` then `flush()` as Restore does, so the `stopped` check, the blank note rule and the save error banner apply with no second write path. It may not stay pending: a restore from All notes keeps its `updatedAt`, so `onChange` would drop it as older and the pending save would bin the note again, and a newer save from another tab would take the title back through the `saver.pending()` branch. A draft is lost when the tab closes, as `pagehide` flushes the saver only. A stopped tab does not open the input; `stop` closes an open one without committing and removes `role`, `tabindex` and the tooltip from `#title`. `.title-hint` is `position: absolute` in a `position: relative` `.header`, above the search dialog's z-index, so it covers the panes: in flow it would move them on open and close, and the mouseup of a click into the editor, which blurs at mousedown, would land elsewhere. A static test pins that.
- `updatedAt` around a rename: `commitRename` stamps `Math.max(Date.now(), note.updatedAt + 1)` and the saver passes `Math.max(Date.now(), note.updatedAt)` to `edit`. `onChange` adopts an equal `updatedAt`, so the echo of an earlier write would take the title back, and the commit has to sit above it itself: `edit` does not stamp a blank note, and a save can share the millisecond. The saver's `max` keeps a save from going below that stamp. The `<` in `onChange` stays and does not become `<=`: All notes `restore` and `trash` keep `updatedAt`, so `<=` would drop them. The fix for an echo belongs on the stamp side.
- Before trashing or removing a note, All notes sends each of its open tabs `runtime.sendMessage({type: 'stop', id, tabId})`; the tab flushes, stops writing and replies once its last write landed. Only then does All notes close the tabs, re-read the key and write. A closing tab's pagehide write is not ordered against `tabs.remove` resolving, so skipping the stop can resurrect the note. A missing reply or failed close is logged and the action goes on (stopped tabs write nothing).

## Structure

- `src/lib/notes.ts` holds all pure logic and must not touch the DOM or `browser.*`. It has named exports: pages import it from `../lib/notes.ts` and tests `require` it directly, and esbuild bundles it into each script, so it has no runtime `marked` import: only `import type`, and functions that need the lexer take it as an argument (`taskOffsets(source, marked.lexer)`).
- Types live in `src/lib/notes.ts` and are exported for the pages. `Note` is the union `LiveNote | BinnedNote` on `deletedAt`, so `daysLeft` and `daysLeftText` on a live note do not compile. `notesFromStorage` casts at the one storage boundary, with no runtime validation; `image:` values and `imageOrphans` cast at their one read site, also unvalidated. `RecentEntry.sessionId` is a `string`: `classify` sends a closed session with no id to other notes, because `sessions.restore(undefined)` restores the latest session. Those guards are deliberate: whether Firefox ever omits the id or a closed window's `tabs` is unverified, and the failure would be restoring the wrong session. `storage.local.get` and `set` are untyped, so a wrong value in `set({ [key]: ... })` compiles: writes pass values already typed `Note` or `Settings`, and reads are annotated where they land. `mermaid` is a `declare const` in `note.ts`, not a global declaration, as the other pages never load it.
- Page sources keep their IIFE wrapper (`note.ts` and `options.ts` use a top-level `return`). `strict` in `tsconfig.json` is what makes esbuild put `"use strict"` at the top of each bundle, and it applies to the whole bundle: CodeMirror addons that were sloppy as plain scripts run strict, so suspect this first if an addon misbehaves only in the build.
- Pages: `src/note/` (one note per tab, `?id=<uuid>`), `src/options/` (Settings: `settings.defaultTitle`, `fontSize`, `theme`), `src/recovery/` (All notes). `src/theme.ts` is the blocking theme script of all three, built to `dist/theme.js`. `src/background.ts` opens a note tab on toolbar click (`openerTabId` = clicked-from tab, which Sidebery nests by; there is no `default_popup`) and purges expired bin entries and sweeps unreferenced images on startup and every 24h (persistent page, so `setInterval`, no `alarms` permission).
- `src/background.ts` and the page scripts are thin glue over `src/lib/notes.ts`. New logic goes there with unit tests. `$` (pages only, typed per page), `warn` and `warnOr` are deliberately duplicated in the page scripts (`warn` and `warnOr` also in background.ts, `warn` also in theme.ts), as is the All notes open-or-focus handler in note.ts and options.ts (tested in both harnesses), rather than shared through `src/lib/notes.ts`, which must not touch `browser.*`.
- Shared styles: `src/styles/base.css` holds the tokens (colour, spacing, radius, control height, fonts), the `color-scheme` rules, `* { box-sizing: border-box }` (which does reach the search dialog), `[hidden]`, the body font, `.error`, `.header` and the `button`, `input` and `select` styles; each page stylesheet `@import`s it and esbuild bundles one file per page. Every `button`, `input` and `select` rule there is scoped to `.header`, `.banner` or `.field`, or it would also restyle CodeMirror's search dialog. `.code-block .copy` is a class selector, so the scoping test does not see it; write it that way, as `.code-block button` fails that test. Page stylesheets use tokens for colours and hold no button rules: `.code-block .copy` joins the shared rules in `base.css`, and `note.css` adds only its position and reveal (by opacity, as a hidden control could not take keyboard focus), and selects boxes as `.preview [type=checkbox]`, since a selector ending in `input` fails the scoping test. Static tests check all of this. `--note-font-size` stays in `note.css`, as the font size test pins it.
- Build: `build(outdir, version)` in `scripts/build.js` empties `outdir` so a removed file cannot linger in the package, but keeps `.amo-upload-uuid`: `web-ext sign` stores it in the source dir, and the release workflow restores it there, so a re-run after a failure between validation and submit reuses the upload (docs/DEVELOPMENT.md, Release). web-ext ignores dotfiles, so it stays out of the package. `version` goes into `dist/manifest.json` only, which is rewritten as parsed JSON, while an unstamped build copies the file as it is; a value that is not `X.Y.Z` throws, and an empty or missing one keeps the placeholder. `RELEASE_VERSION` is read only under `require.main`, as the suite runs inside `task sign` with it set. `bundleOptions` is shared with `tests/bundle.js`, so the harnesses run what ships. Its `target` matches `strict_min_version` in the manifest, and a test holds them together: raise both, or esbuild keeps downleveling for a version no longer supported, or emits syntax a supported version cannot parse. `build()` writes `THIRD_PARTY_LICENSES.txt`, and a non-dev package with no license file fails it, unless it is in `README_LICENSES`; for those, `thirdPartyNotices` takes the text from the `## License` section of the README; an optional package that is not installed is skipped. A file the extension needs is added to the build's lists, and `tests/build.test.js` holds the exact top level of `dist/`.
- `docs/plans/` is gitignored: plans are local working files, never committed.
- Taskfile: `build:dist` is a dep of `lint` only. `build` and `sign` already depend on `lint`, and task deps run in parallel without deduplication, so a second dep would run two builds that delete each other's output. `npm ci` is a workflow step, never a dep of `sign`, where it would delete `node_modules` while `test` runs in parallel. `sign` is the entry point of the release workflow: a precondition refuses it without `RELEASE_VERSION`, so a local run cannot burn `0.0.0`, and it has no `status`, as nothing reuses a signed xpi on a fresh runner. AMO credentials come from the environment. `sign` uploads a `git archive --format=zip HEAD` of the commit with `--upload-source-code`, as `web-ext-artifacts/source-<RELEASE_VERSION>.zip`: not an `.xpi`, so the artifact upload (`*.xpi`) and the `*-<version>.xpi` glob of `gh release create` skip it. Its first command refuses a dirty tree (`git status --porcelain`, which skips the ignored `dist/`, `node_modules/`, `web-ext-artifacts/` and `docs/plans/`), because `dist/` is built from the tree and the zip from `HEAD`. docs/DEVELOPMENT.md keeps the build instructions AMO reviewers need.
- Storage: `note:<id>` = `{title, content, updatedAt, deletedAt}`, `settings` = `{defaultTitle}` (a template, stored unexpanded), `fontSize` = px number (10..32, default 14, via `fontSizeFrom`), `theme` = `'system' | 'light' | 'dark'` (default `system`, via `themeFrom`), `image:<uuid>` = `{dataUrl}`, `imageOrphans` = `{<uuid>: firstSeenAt}`. A note is written only once it has content; blank content removes the key unless the note is binned. The note page keeps the note in memory so the save on `pagehide` is one synchronous `storage.local.set` / `remove` with no `await` before it.
- All notes rows: `rowText` names a note whose title is a default by its first heading outside a fence, else its first line with plain text, else its first code line, never empty, as the name labels the row's button and checkbox. A default title is `DEFAULT_TITLE` or the text of `settings.defaultTitle`: an expanded template differs from it, so such a note shows its title, which is accepted as the user chose that template, and a note renamed to exactly that text is named by its content. `matches` skips a default title for the same reason it is not shown, and `searchParts` uses an escaped regex, as `toLowerCase()` indexes shift on `İ`. Name and full preview are computed once per `refresh()`, as search renders on every keystroke. `plainPreview` is regexes, as `notes.ts` has no runtime marked. A row's first action moves into its main area, keeping the action in `aria-label` and `title`, as a click can reopen a whole window; a Bin row has none. Page stylesheets may not contain the word `button` even in a class name, hence `.row-main`.
- All notes selection is page state (`selected`, `scope`, `anchor`), as `refresh()` replaces every row. Live and Bin selections stay apart. Pruning in `render()` is by the scope's own sections, not all visible rows: a Bin selection keeping a note restored elsewhere would make Delete forever remove a live note. The Bin's `open` is never set by `render()`, only on search transitions, or a refresh would reopen a Bin the user closed; its select all and Empty bin sit outside `summary`.
- All notes bulk runs (`bulk`) cover row actions too: they take their items up front, clear the selection and ignore clicks while `busy`, as a second trash resets `deletedAt`. Storage and tab events still render during a run. Every item action re-reads after `closeTabs` and returns `written`, `gone` or `failed`: `removeItem` skips a note no longer binned, as `confirm()` blocks this page while note tabs run, and `trashItem` skips one already binned. `gone` is not counted in the status line. `undo` holds only ids that were written, and a partial Undo keeps the failed ones for a retry. Undo has no timer, and does not reopen tabs.
- Recovery refreshes: each `refresh()` gets an increasing id and only applies if no newer refresh has applied yet, so a slow older refresh cannot overwrite a newer one, while a failed newer one does not block it. `tabs.onUpdated` refreshes only when `changeInfo.url` is set (title/status/favicon changes cannot move a note); `tabs.onAttached` / `onReplaced` refresh because they change `windowId` / `tabId`.
- Release: pushing a `vX.Y.Z` tag runs `.github/workflows/release.yml`. The tag is the version and CI commits nothing back, so the root `manifest.json` stays `0.0.0`, also in the source zip AMO gets (docs/DEVELOPMENT.md, Building from source). There is no local release flow. `scripts/release-notes.js` is a dependency-free node script outside the package (only `dist/` is packaged, and `tests/static.test.js` does not scan `scripts/`). Release logic stays there, not in `src/lib/notes.ts`, which ships in the package. Pure functions are exported for tests, and the flow runs only under `require.main === module`. Commit and PR text is untrusted input to Claude: it runs with `--tools ''` and no `WEB_EXT_*`, `GH_*` or `GITHUB_*` variable. Do not pass `--bare` to `claude`: it skips OAuth. Any Claude failure falls back to notes from conventional commits and PR titles, and the publish step uses `--generate-notes` if no file came out, so a notes failure never blocks a release. The range starts at the highest lower tag with a GitHub release, so a burned tag adds no gap; with no list of releases, at the highest lower tag; with no earlier tag, it is all history. AMO signs a version once, so nothing is rolled back or retried automatically. Recovery flow: docs/DEVELOPMENT.md, Recovery. `SOURCE` is `--source-dir dist`, so `web-ext-artifacts/` and everything else outside the build cannot reach the package, and it needs no ignore list.
- Workflows: a tag-triggered workflow runs the file of the tagged commit, so nothing in the file binds someone who can push that commit and tag. Repo settings are the boundary: the tag ruleset on `refs/tags/v*` and the `release` environment with a tag-type deployment policy, as a branch-type entry would let a branch named `v1.2.3` through. The checks in `release.yml` are a second layer, for mistakes and a lost setting. Runs are serialized per tag by `concurrency`. `guard` holds no secrets and checks the strict tag, that the commit is on `origin/main` and that the tag is the highest strict tag, so a mistyped lower tag stops before signing; that limits the trigger, not the content. Both jobs carry the actor `if`: "Re-run failed jobs" does not re-run a `guard` that passed, while a job-level `if` is evaluated again. The trigger stays tag pushes only, with no `workflow_dispatch`, `repository_dispatch` or `workflow_run`, and `ci.yml` stays `push` to `main` and `pull_request`, never `pull_request_target`, with no secrets or `environment`. No `${{ }}` in `run:`: a git ref can hold `$(...)`, so values reach shell through `env`, like `TAG`. Secrets live in the `release` environment, each in `env` of the one step using it, and the Claude step holds no other credential. `permissions: {}` at the top, with `contents: read` on jobs, except `release` with `contents: write` and `pull-requests: read`. Actions are pinned to full SHAs, checkout has `persist-credentials: false`, and `release.yml` has no `setup-node` cache, as a restored cache would write into the job holding the AMO credentials; `package-manager-cache: false` is there because setup-node caches by itself once `package.json` has `packageManager`. The upload uuid cache is the one accepted exception (docs/DEVELOPMENT.md, Known limitations). Node and task versions match in both workflows, and a CI pin is bumped as docs/DEVELOPMENT.md, Updating dependencies says. `gh pr list --limit` stays under 50: with `--json commits`, 50 or more is over GitHub's 500,000 node limit and always fails, and an older PR just shows as commit subjects. The xpi artifact is uploaded right after signing, before anything else can fail, as AMO cannot sign the version again. A cache key is immutable, hence the run id and attempt in the uuid key.

## Tests

```
npm ci         # first, on a fresh checkout or after a lockfile change
task test      # tsc --noEmit, then node --test
task lint      # builds dist/, then the AMO linter
```

- Node built-in runner only. Do not pass a bare directory (Node 21+ treats args as globs).
- `tests/workflows.test.js` reads the workflow files as text, as there is no YAML dependency, and runs their shell blocks under bash in a temp repo with `gh` and `task` stubs. Both this test and `tests/release-notes.test.js` set up their repo through `tests/gitrepo.js`, which `node --test` does not pick up. It cannot prove they run on GitHub: that behaviour is in docs/DEVELOPMENT.md, Manual verification. `tests/release-notes.test.js` runs the script in a temp git repo; its `PATH` holds only a `claude` stub and links to `git` and `node`, so real `claude` cannot be reached.
- Tests stay JavaScript: typing the fake DOM harnesses would add a large surface for no extra checking of the code under test. Type checks are `tsc --noEmit`, in `task test` (`npx --no-install`, so a missing install fails instead of fetching typescript); `task lint` stays the AMO linter only.
- `tests/background.test.js`, `tests/note.test.js`, `tests/options.test.js`, `tests/recovery.test.js` and `tests/theme.test.js` evaluate a test bundle of the real entry (`tests/bundle.js`, compiled once per harness) in a `node:vm` context with a fake DOM and a `browser` stub. Extend those harnesses when page glue changes. The note harness runs the real marked, highlight.js and CodeMirror, but aliases `codemirror/lib/codemirror.js` to `tests/codemirror-shim.js`: the shim requires the real file by relative path (the aliased path would resolve back to the shim), points `fromTextArea` at a hook the harness sets on `ctx`, which returns a fake editor (getValue/setValue/on('changes')/on('scroll')/operation/selection/replaceRange/posFromIndex/heightAtLine/getScrollInfo/scrollTo/getWrapperElement; focus refuses and setOption blurs under `readOnly: 'nocursor'`, like the real one), and sets `globalThis.CodeMirror` for the tests that read `ctx.CodeMirror`. Production code has no seam. The harness also stubs mermaid and `<script>` loading via createElement/head.appendChild, since a real editor and mermaid need a real DOM, and `matchMedia` with a fireable `change` (`systemDark`, `setSystemDark`). `tabs.getCurrent` resolves to the `tab` option, `openerTabId` included, and `tabs.get` to `sourceTab`, held by `holdSource` until `releaseSource()`. Elements have `select()`, and `focus()` dispatches no blur on the previous element, so rename tests dispatch it themselves. The `hidden` table in the `note.html` test and `els` in the options harness mirror the pages, so a new id goes there too: an id missing from `els` is `undefined` and every options test throws. The theme harness has a fake `localStorage` that can throw on read or write. Layout and clipboard are fake too (`offsetTop`, `scrollHeight`, `clientHeight`, overridable through `layout`, a stubbed `navigator.clipboard`, focusin dispatched on focus): scrollTo fires no scroll event, tests fire scroll themselves, and real scrolling, clipboard and layout are manual checks in docs/DEVELOPMENT.md. For images the fake editor adds `on('drop')`, `on('paste')`, `coordsChar` (records its arguments in `coords`), `markText` (its range moves with `replaceRange`, and `find()` turns undefined after `setValue` or an edit covering it; a test pins these facts on a real headless `CodeMirror.Doc`), `replaceRange` (records origins in `replaced`), `getScrollerElement` (with a parent-walking `contains`), `fire` for delivering editor events and `focus`, and the harness adds `crypto`, `FileReader`, `filesRead`, the `image-error` and `save-error` elements, `img[data-image]` nodes parsed from the preview HTML, `imageReads` to hold or fail reads of `image:` keys and `fileReads` to hold file reads; `set` and `remove` update `storage` once they land. The background and recovery storage stubs have `getKeys` and filter `get` by keys, and tests check that `image:` keys are never requested there. The background stub also has `set`, a mutating `remove` and an adjustable clock (`sweepAt`); the recovery harness records refresh reads in `reads`, not `calls`, and adds `tick`, `tickAll` and `press` (keydown) for selection and a function form of `reject` that decides by the call's arguments, for partial failures. Row layout has no fake: static tests pin its CSS, and a headless Firefox screenshot of `dist/recovery` over a stub `browser` is how to look at it. A dropped CodeMirror mode or addon fails nothing else, so adding or removing an import in `note.ts` means updating the exact mode list and addon checks in tests/note.test.js.
- Icons: `node scripts/gen-icons.js` regenerates `icons/*.png`.

## Debugging

- `task install:debug` builds and starts Firefox with the add-on loaded. In WSL that is the Windows Firefox via `scripts/install-debug.ps1`, which speaks the remote debugging protocol from PowerShell: Windows has no node, and under NAT networking WSL cannot reach the debugger port. `task install:debug` calls `node scripts/build.js` directly, since a `build:dist` dep is reserved for `lint`.
- Or run `task build:dist`, then load `dist/manifest.json` in `about:debugging#/runtime/this-firefox`. The root `manifest.json` names build output and does not load.
- `about:debugging#/runtime/this-firefox` > tabnotes > "Inspect" opens devtools for the extension (background script); open a note, All notes or Settings tab while it is attached. A temporary add-on gets a new uuid on each load, so old note tabs break.
- All warnings from the pages start with `tabnotes:`; filter the console by that prefix.
- Stored notes are in the devtools Storage tab > Extension Storage.
- The mode is `data-theme` on `<html>`; the first-paint mirror is `theme` under Local Storage in devtools, separate from Extension Storage. Delete it to reproduce the first-paint flash. `prefers-color-scheme` follows Firefox Settings > General > Website appearance, so System tracks the OS only when that is Automatic.
- `task lint` warns about `eval` / `Function` (DANGEROUS_EVAL) and `innerHTML` inside `dist/vendor/mermaid.min.js`, and about `innerHTML` in the third-party code in the bundled `note/note.js`. The MV2 CSP blocks `eval`, which tests cannot catch: after a mermaid update, render a diagram and check the console for CSP errors.
